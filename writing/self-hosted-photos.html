Escaping Google Photos: migrating 25GB and 14,700 photos to a self-hosted server

My free Google One student storage (2TB, part of a promo for Indian students) expired on July 31, 2026. Rather than pay for space I didn't need to be locked into, I decided to pull everything out and self-host it instead.

The problem with "just export your photos"

Google Takeout doesn't hand you a clean photo library — it hands you a mess. Photos are split across dozens of folders (one per album, plus year-based folders), often duplicated if a photo lived in more than one album. Worse, the actual capture date and GPS location aren't reliably written into the image files themselves — they're stored separately in .json sidecar files next to each photo. Dump that into any normal viewer and everything sorts by "date downloaded," not "date taken." 25GB of memories, all showing up as if they were taken on the same day.

The decision

I went with Immich — an open-source, self-hosted Google Photos alternative — running in Docker on my Windows laptop via Docker Desktop and WSL2. To fix the Takeout export itself, I used immich-go, a CLI tool built specifically to read Takeout's folder structure, merge the JSON sidecar metadata back into each file, dedupe copies across albums, and upload the result directly into Immich in one pass.

The part that actually taught me something

Partway through the initial processing (Immich has to extract metadata, generate thumbnails, and run face/ML tagging on every asset after import), my laptop went to sleep after I closed the lid without thinking. When I reopened it, Docker Desktop showed the Immich containers as "running" — but the job queue had ~36,000 pending tasks and wasn't moving. No error, no crash, just silence.

The fix turned out to be simple (docker compose restart), but getting there meant actually diagnosing it rather than guessing: checking Docker Desktop's CPU usage panel and seeing it sitting at ~10% total across all containers — nowhere near what a real processing job should look like on a 12-core machine. That mismatch between "status: running" and "actual work: not happening" was the tell that WSL2's sleep/wake cycle had silently stalled the worker processes without killing the containers outright.

Small bug, but it's the kind of thing you only learn by actually running infrastructure yourself rather than reading about it.

Where it landed

The library now lives locally, browsable at localhost:2283, fully searchable (including ML-based tag search — "beach", "dog" — that Immich generates itself), with the original Takeout export kept as a secondary backup on an external drive. No cloud dependency, no recurring storage bill, and one bug diagnosed and fixed along the way.
